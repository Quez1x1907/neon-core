# Архитектура и важные решения
- Игровой цикл трёхступенчатый: rAF → Web Worker-тикер (в Telegram-вебвью rAF мёртв!) → setInterval-страховка. Логика фиксированным шагом 1/60, скорость ×2 = два шага. tick() обёрнут в try/catch — цикл неубиваемый; reportErr пишет ошибку в консоль, window.__errs, localStorage 'nc_errs' (видно в Настройках как «Последняя ошибка») и показывает тост раз в 5с.
- Все сущности в пулах (EP/BP/PP/FP/TX), предрендер фона в offscreen-canvas (с блидом 24px под тряску, рисуется 1:1 — НЕ растягивать, иначе сетка уползает на телефоне), частицы ограничены. В портрете поле прижато к HUD (V.oy=2).
- Экраны конца партии (victory/defeat) — sticky модалки: тап по фону и Esc их не закрывают; страховка переоткрывает окно, если оно исчезло.
- Сейв в localStorage + зеркало в Telegram CloudStorage, ключ по пользователю. victory/defeat/waveClear обёрнуты в try/catch с фолбэком — конец партии не может заморозить игру.
- Авто-низкая графика: если FPS < 25 дольше 4с — S.lowgfx=true (DPR 1, без глоу у врагов, меньше частиц).

# Баланс (настроен, не ломать без нужды)
- Экономика строгая: награды ×0.7, после 10-й волны затухание ×0.96^wave, бонус за волну 15+2×wave, майнер слабый, цены улучшений +25% от базовых. Симуляцией проверено: кампания 1 проходима, к концу ~2-3k свободных — «прокачать всё» нельзя.
- Карты по возрастанию: mult 1.0/1.12/1.22/1.28/1.46/1.52/1.6/1.6, «прогрев» — на дорогих картах HP-множитель разгоняется к 10-й волне (warm 0.55+0.45×min(wave,10)/10), HP растёт ×1.115 за волну.
- Способности: EMP cd 45с/стан 2.2с (босс ×0.5), Overdrive cd 60с/+60%/6с.

# Известные особенности среды тестирования
- Встроенный браузер (IAB) душил rAF и таймеры страницы до ~1 Гц — воркер-тикер это компенсирует (проверено 60+ FPS). Скриншоты иногда падают ошибкой capture — просто повторить через 1-2с.
- Автотесты делаются через хуки window.__ND (cash/cores/wave/win/lose/give/step(sec)/frames) и прямые вызовы глобальных функций; автоигрок = билд-ордер + автоапгрейд + выбор веток.
- При длительных запусках в IAB остаётся старый localStorage github.io — перед чистыми тестами чистить ключи 'neoncore_v1' и 'nc_errs'.

# Задача
Продолжай улучшать игру по инструкции пользователя (он просит «продолжай улучшать» и сам скажет, когда остановиться). Каждый раунд: внедрить блок улучшений → cat src/* > index.html → node --check → протестировать в браузере (desktop + mobile viewport 390×760 и 760×390, девственный сейв) → деплоить на Pages → кратко отчитаться. Бэклог: метки веток на иконках в панели строительства, раздельная громкость звуков, экран профиля со статистикой, новые карты с 3–4 путями. Не ломать перечисленные защитные механизмы и баланс. Если пользователь сообщает баг — сначала воспроизвести и найти причину, потом чинить.
